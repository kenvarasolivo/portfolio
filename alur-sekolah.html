One school, different needs.

Teachers manage a class, families follow a child’s school day, and administrators keep the school organised. Alur brings attendance, assignments, grades, announcements, classroom documentation, and messaging into one platform with views shaped around those roles.

A shared school day.

Explore the different roles. Each sees the part of school life relevant to them.

  1. Teachers
  2. Families
  3. School admins
  4. Students

Class → attendance, assignments, updates

Run the classroom.

Teachers work with class rosters, record attendance, manage assignments and grades, and share announcements or classroom documentation from the web workspace.

Child’s class → updates + school messages

Stay close to the school day.

Parents can follow their child’s class feed and communicate with the school. Classroom updates and messages sit together instead of becoming disconnected pieces of information.

School workspace → classes + people + permissions

Keep the school organised.

Administrators manage the school workspace and its classroom structure. The backend separates school data by tenant and applies role-based access to the shared API.

Assigned work → submission → feedback

Know what comes next.

Assignments and grades connect the classroom’s learning activities to a student’s own work. These use the same backend as the teacher and family experiences.

Direction through implementation.

Shape the product

Lead product and design direction: define how the different school roles fit together, structure the experience, and turn the platform’s scope into understandable web flows.

Design the experience

Designed the web experience from the public landing page to the signed-in workspace, with a consistent visual direction and role-specific navigation for school staff and families.

Build the full-stack web app

Built the React and TypeScript website and its backend integration, connecting the interface to FastAPI, PostgreSQL data, and Keycloak sign-in. My ownership here is the web product within our team.

One backend, distinct experiences.

The platform has a shared FastAPI backend for the React web client and a separate Expo mobile client. PostgreSQL stores school data with a schema per tenant, and Keycloak handles sign-in. I built the full-stack website; the mobile client is part of the wider team project.

  1. React web / Expo mobile
  2. FastAPI + Keycloak
  3. PostgreSQL per school

A product in development.

The web workspace is connected to the API for core school workflows, from class information to communication. We are continuing development as a four-person team. My focus is carrying the web product from product and design decisions into a working full-stack experience.
