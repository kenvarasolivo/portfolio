Automated Grading

Solo university project · Full-stack & Applied AI

2026

From submission to a reviewable grade.

I designed and built an assessment workflow for programming assignments from end to end. It turns assignment sheets into rubrics, runs code in Docker, and drafts feedback for a lecturer to review.

Make grading inspectable.

A programming submission can contain working code, failing tests, and written explanations. These need different kinds of assessment. I built a workflow that keeps test evidence, rubric criteria, and feedback together, with a lecturer making the final decision.

Evidence before a grade.

Explore the core assessment path. Every automated result remains a draft until lecturer approval.

  1. Define the rubric
  2. Run the tests
  3. Draft assessment

Assignment PDF + lecturer tests → reviewed rubric

Make the criteria explicit.

The parser turns the assignment PDF into a structured rubric. A lecturer reviews the criteria and points, or imports an existing rubric, before submissions are assessed.

Passed tests / runnable tests × criterion points

Let tests determine code scores.

Python or Java submissions run against the lecturer’s tests in an isolated Docker container. Deterministic points come from passed versus runnable tests; the language model cannot change that score.

Rubric + evidence → bounded awards + feedback

Use AI where interpretation helps.

The model assesses written answers against the rubric and explains failing traces. Awards are bounded by criterion limits. A verifier checks the draft against the evidence and flags uncertainty for review.

Automated draft → review → approved result

Keep the final decision human.

The lecturer inspects evidence, reviews flagged criteria, edits the draft when needed, and approves the result. A generated assessment is not an official grade on its own.

Built from end to end.

Design both sides

Designed and implemented student submission flows and the lecturer workspace: module selection, assignment setup, rubric editing, review queues, and result history.

Build the assessment pipeline

Implemented the LangGraph pipeline, structured rubric parsing, Python and Java test execution, selective model assessment, and evidence verification behind a FastAPI backend.

Make results reviewable

Connected test evidence and criterion-level feedback to the review interface. Preserved deterministic scoring and made uncertain or disputed criteria visible for lecturer review.

Two kinds of assessment.

Test-based criteria use deterministic scoring. Written answers and failure explanations use the model selectively. LangGraph coordinates the stages; FastAPI serves the API and web interface. Keeping these responsibilities separate makes it possible to inspect how a draft was produced.

A working assessment MVP.

The core parse, execute, and grade flow works end to end for Python, Java, and written answers. This remains a university MVP with lecturer review. Production authentication and infrastructure self-healing are outside the implemented core described here.
